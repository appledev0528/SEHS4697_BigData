### 🟦 Code — Read & Filter Data + Split

```r
# Step 1: Read cleaned data and keep valid Superhost rows
df = read.csv("listings_clean.csv", stringsAsFactors=TRUE)
df = filter(df, host_is_superhost == "Yes" | host_is_superhost == "No")

# Step 2: 80/20 train-test split with fixed seed (reproducible)
set.seed(56109111)
pname = sample(x=c("train","test"),
               size=nrow(df),
               replace=TRUE,
               prob=c(0.8,0.2))
data_train = df[pname=="train",]
data_test  = df[pname=="test",]
```

## Slide 3 — Data Challenge + Modeling Approach

**⏱ ~50 seconds**

### Script
> "Here is the critical challenge I discovered. Running `table(data_train$host_is_superhost)` showed 3,815 Non-Superhosts versus only 542 Superhosts — an 87.5% to 12.5% split. This is a severely imbalanced dataset. Without fixing this, a naive model could achieve 89.3% accuracy just by predicting 'Not a Superhost' every time — but it would never identify any Superhost at all. So I applied the Lecture 6 solution: `sampling='up'` in `trainControl`."

### 🟦 Code — Check Class Imbalance

```r
print("Distribution of Superhost in Training Data:")
table(data_train$host_is_superhost)
```

### 📤 Actual R Output

```
[1] "Distribution of Superhost in Training Data:"

  No  Yes
3815  542
```

📌 What this means:
- **3,815 Non-Superhosts (87.5%)** vs **542 Superhosts (12.5%)** in training data
- Severely imbalanced → model will be biased toward always predicting "No" without correction
- Fix: `sampling="up"` duplicates Superhost rows until both classes are balanced

### 🟦 Code — Build the Model

```r
# Up-sampling + 10-fold CV (Lecture 6 key technique)
train_ctl = trainControl(method="cv", number=10, sampling="up")

# Decision Tree classifier with 5 predictors
model <- train(host_is_superhost ~ price + accommodates + review_scores_rating +
                 number_of_reviews + instant_bookable,
               data=data_train,
               trControl=train_ctl,
               method="rpart")

# Visualise the decision rules
rpart.plot(model$finalModel)
```

### 📤 Output
> `rpart.plot()` generates a tree diagram in the RStudio Plots pane (visual only, no text output).  
> The tree root node splits on `review_scores_rating` — confirming it is the #1 predictor.

## Q&A Preparation

### Q1: "Why did you choose Decision Tree over Logistic Regression?"
> "Decision Tree produces interpretable if-else rules — the `rpart.plot` output shows exactly which threshold on `review_scores_rating` triggers a Superhost prediction. This is directly actionable for a host. Logistic Regression would give coefficients that are harder to translate into concrete advice."

---

### Q2: "Your accuracy 84.1% is lower than the baseline 89.3% — isn't the model worse?"
> "Raw accuracy is misleading on imbalanced data. The 89.3% No Information Rate comes from always predicting 'Not a Superhost' — it never identifies a single Superhost. Our model achieves **Sensitivity of 72.3%**, correctly identifying 81 out of 112 actual Superhosts in the test set. Our Kappa of 0.41 versus a baseline Kappa of exactly 0.00 proves our model is genuinely learning."

Relevant output to point to:
```
No Information Rate : 0.8927   ← "always say No" baseline
Kappa               : 0.4106   ← our model's genuine learning
Sensitivity         : 0.72321  ← 72.3% of Superhosts correctly found
```

---

### Q3: "What does `sampling='up'` actually do?"
> "Up-sampling replicates Superhost rows in the training data until both classes are balanced. Our training data had 3,815 Non-Superhosts and only 542 Superhosts. `sampling='up'` randomly duplicates Superhost rows until we have approximately 3,815 of each — so the model sees equal examples during the 10 cross-validation folds."

Relevant output to point to:
```
table(data_train$host_is_superhost)
  No  Yes
3815  542    ← Before up-sampling: 87.5% vs 12.5%
```
```r
train_ctl = trainControl(method="cv", number=10, sampling="up")
#                                                ^^^^^^^^^^^
#                           This line fixes the imbalance (Lecture 6)
```

### Q6: "What is Kappa and why does it matter?"
> "Cohen's Kappa measures agreement beyond chance. A Kappa of 0 means no better than random guessing; 1.0 means perfect. Our **Kappa = 0.4106** (moderate agreement). On imbalanced data, a model that always predicts 'No' gets high accuracy but Kappa = 0. Our 0.41 confirms the model is genuinely learning Superhost patterns."
